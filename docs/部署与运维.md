# 部署与运维

> 面向"要在一台机器上装、升、卸、查"的人。协议细节见 [协议-门户.md](协议-门户.md)，
> 设计取舍见 [架构.md](架构.md)，事故案例见 [历史与根因.md](历史与根因.md)。

## 1. 安装 / 升级 / 卸载

三者均需**管理员终端**（UAC）。托盘与 `status` 不需要。

**安装目录可配置**：`install --dir <绝对路径>`，默认 `C:\Program Files\NetAnchor-Campus`。
已安装后，`upgrade` / `uninstall` / `status` 一律以**服务注册的 ImagePath** 为准（辅以安装时写入的 HKLM 记录），换盘符或自定义路径后其余命令仍然正确。

| 操作 | 步骤 | 失败处理 |
|---|---|---|
| install | 建目录 → 复制文件 → 创建服务（LocalSystem、auto-start、指向实际目录）→ 设置失败恢复动作 → 写初始配置模板 → 记录安装目录 → 写机器级托盘自启 → 启动 | 任一步失败回滚已做步骤，非零退出码 |
| upgrade | 停服务 → 结束托盘/OCR → 备份当前目录 → 删除旧目录 → 复制新文件 → 重写托盘自启项 → 启动 | 从停服务开始的所有步骤纳入恢复：还原文件并回到升级前运行状态 |
| uninstall | 停服务 → 结束托盘/OCR → 删托盘自启项 → 删文件 → 删服务 → 询问后删 `%ProgramData%` | 文件删不掉时**保留服务**（已停止），状态可恢复 |

要点：

- 需要管理员的动作：创建目录与服务、写 ACL、设置恢复策略、写 `HKLM` 自启项
- 安装不写任何用户目录、不注册计划任务、不创建快捷方式、不依赖 vbs/bat
- **升级是"干净安装"**：先删旧目录再复制。只覆盖不删除会把上一版独有的文件留下（`pywintypes314.dll` 就是这样坑过一次）
- **不能从安装目录里运行 `upgrade`**：会锁住 `NetAnchor.Cli.exe` 自身。0.2.2+ 会自动改用发布包里的 CLI，0.2.1 会直接失败
- 宿主机升级建议用 `uninstall`（保留配置）+ `install --dir`，比 `upgrade` 稳（目录被占用时 `upgrade` 会回滚）

## 2. 托盘开机自启（0.2.5 起为机器级）

注册项由**安装程序**写、卸载时删，全体本地用户登录都会拉起托盘：

- `HKLM\Software\Microsoft\Windows\CurrentVersion\Run\NetAnchor-Campus Tray` = `"<安装目录>\NetAnchor.Tray.exe" --autostart`
- `install` / `upgrade` 写（换目录后指向新路径），`uninstall` 删
- 用户级开关存 `HKCU\Software\NetAnchor-Campus\TrayAutostart`（默认开启）：关掉后，托盘被自启拉起时读到开关即退出；**手动双击不受影响**
- `--autostart` 是区分"自启"与"手动启动"的标记；自启拉起的重复实例静默退出，不弹框
- 菜单里仍是「开机自启托盘: [已启用]/[未启用]」；关闭只能清当前用户的 HKCU 残留，删 HKLM 需要管理员

为什么 0.2.3 的 HKCU 方案不行：自启项由托盘自己写，**哪个用户没启动过托盘，那个用户就没有自启项**（真机验证：只有运行过托盘的那个账户有 `Run` 值，切到其他本地用户后托盘根本不启动）。

## 3. 日志

| 来源 | 位置 | 轮转 |
|---|---|---|
| 服务 | `%ProgramData%\NetAnchor-Campus\logs\service.log` | 按天，保留 7 份 |
| 托盘 | `%LOCALAPPDATA%\NetAnchor-Campus\logs\tray.log` | 按天，保留 7 份 |

为什么分开：配置目录的 ACL 只给 `SYSTEM`/`Administrators`，托盘以普通用户运行写不进去。

日志不含密码、`upass`、完整请求串；账号只留前 3 位。托盘日志包含：启动/退出、单实例退出、IPC 失联与恢复、菜单动作、自启开关变更、会话结束。

## 4. 日常命令

```powershell
# 服务
sc.exe query NetAnchorCampus
sc.exe stop  NetAnchorCampus
sc.exe start NetAnchorCampus
sc.exe config NetAnchorCampus start= demand   # 关开机自启
sc.exe config NetAnchorCampus start= auto

# 维护
& '<安装目录>\NetAnchor.Cli.exe' status
& '<安装目录>\NetAnchor.Cli.exe' uninstall [--purge]

# 日志
Get-Content 'C:\ProgramData\NetAnchor-Campus\logs\service.log' -Tail 50 -Wait
Get-Content "$env:LOCALAPPDATA\NetAnchor-Campus\logs\tray.log" -Tail 50 -Wait
```

## 5. 排障顺序

按"服务 → IPC → 托盘 → 网络"的顺序看，别一上来怀疑网络：

1. **服务在不在**：`sc.exe query NetAnchorCampus`；`RUNNING` 但没日志说明起不来，看 Application 日志的服务事件
2. **IPC 通不通**：`\\.\pipe\` 里有没有 `NetAnchor.Campus.v1`；托盘报"无法确认服务端身份"多半是身份校验（历史案例见 [历史与根因](历史与根因.md)）
3. **托盘在不在**：进程有没有、`tray.log` 最后几行是什么；托盘崩溃不会自愈，要重新登录或手动启动
4. **网络**：先看状态是 `online` 还是 `portal_unreachable`；后者会带出具体失败原因（`门户候选均探测失败：<host>: <异常>`）
5. **登录被拒**：看 `登录结果 result=<码> msg=<msga>`，对照 [协议-门户 · 响应与错误](协议-门户.md)

常见形态对照：

| 日志 / 现象 | 含义 |
|---|---|
| `portal_unreachable（... getaddrinfo failed）` | 门户地址非法（曾因填成完整 URL） |
| `portal_unreachable（... timed out）` | 门户不可达：真离线、代理劫持、或 AC 拦 |
| `登录失败 result=0 userid error1` | 账号不存在：核对学号与运营商后缀 |
| `登录结果 result=1` 后仍离线 | 登录成功但复检未过：看 `check_url` 是否被拦 |
| 托盘"与服务失联：管道的另一端上无任何进程" | 服务端管道实例重建空窗；0.2.6+ 会自动重试 |
| Application 日志 `10001 试图否决关机: NetAnchor.Tray.exe` | 托盘未响应会话结束消息；0.2.7+ 已修 |

## 6. 凭据与隐私

- 凭据只在 `%ProgramData%\NetAnchor-Campus\config.json`，Machine DPAPI 加密且绑定门户地址
- 改门户地址必须重输密码（否则返回 `reauth_required`）；改了地址后旧密文不可解，状态变为 `config_missing`
- 实测记录写 `.dsh/`（已 gitignore），不入库；仓库文档只用占位
