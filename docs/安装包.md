# 安装包

> 面向发布者：怎么构建、三条流程各做了什么、失败如何回滚。
> 手动安装/升级/卸载的命令行方式仍见 [部署与运维.md](部署与运维.md)，二者共用同一套 CLI 实现。

## 1. 交付物

| 文件 | 说明 |
|---|---|
| `dist\installer\NetAnchor-Campus-<版本>-setup.exe` | 唯一分发物 |
| `dist\installer\SHA256SUMS.txt` | 安装包 SHA256 |

**不提供 Portable ZIP**：当前架构依赖 Windows Service，纯 onedir 目录无法提供同等能力，还会引入独立的运行、配置与更新生命周期。若将来需要免安装形态，应先设计"无服务运行模式"，而不是直接发目录。

## 2. 构建

前置：**Inno Setup 6**（构建机装，不进用户机器）。
简体中文语言文件**随仓库分发**，位于 `build\languages\ChineseSimplified.isl`，来源与更新方式见 `build\languages\README.md`。
不依赖编译器自带译文：Inno Setup 6.7.3 的 `Languages\` 目录实测**没有**简体中文，若改用 `compiler:Languages\ChineseSimplified.isl` 会直接编译失败。

```powershell
pwsh -File build\make_installer.ps1              # 完整：PyInstaller + ISCC
pwsh -File build\make_installer.ps1 -SkipBuild   # 复用 dist\NetAnchor-Campus，只重打安装包
```

脚本行为：

1. 从 `src\netanchor\__init__.py` 读版本号（唯一来源），经 `/DAppVersion=` 注入 `.iss`
2. 校验 `ChineseSimplified.isl` 存在，**缺失即失败**——不允许静默产出英文安装包
3. `PyInstaller build\netanchor.spec` 生成 onedir
4. 校验 `dist\NetAnchor-Campus\NetAnchor.Cli.exe --version` 与源码版本一致；不一致即中止
   （`-SkipBuild` 重打安装器时容易把上一版的可执行文件打进新版包）
5. `ISCC build\installer.iss` 生成安装包
6. 写 `SHA256SUMS.txt`

机器上装了多个 Python 时，用 `-Python` 指定那个装了 PyInstaller 与依赖的：

```powershell
pwsh -File build\make_installer.ps1 -Python 'C:\Python314\python.exe'
```

关键 `.iss` 配置：

| 项 | 值 | 理由 |
|---|---|---|
| `AppId` | `{F99630C5-8D04-487D-A21D-216BBD46F3C1}` | 固定 GUID，升级与卸载靠它认主，**后续版本不得改动** |
| `MinVersion` | `10.0.14393` | 与"Windows 10 1607+"的支持声明一致 |
| `PrivilegesRequired` | `admin` | 要建服务、写 HKLM |
| `ArchitecturesAllowed` | `x64compatible` | 服务与 pywin32 只有 64 位 |
| `LanguageDetectionMethod` + 语言顺序 | `none`，简体中文在第一位 | 中文是默认语言，不随系统语言漂移 |
| `SignTool` | 空 | 暂无证书，留接口 |

## 3. 三条流程

安装包只做「UAC、向导、铺文件、调度 CLI」，服务生命周期仍由 `NetAnchor.Cli.exe` 执行。

### 全新安装

```
UAC → 向导（许可 / 目录 / 任务：开机自启托盘 [✓]）
→ [Files] 铺 payload 到 {app}
→ postinstall: NetAnchor.Cli.exe register --dir "{app}" [--no-autostart]
→ 成功后可勾选"立即启动托盘"（runasoriginaluser，非提权）
```

### 升级

```
检测到 HKLM\SYSTEM\...\Services\NetAnchorCampus  → 按升级处理，目录页锁定
→ prepare：停服务 → 请托盘与 OCR 退出（失败即中止，旧版本分毫不动）
→ {app} 重命名为 {app}.previous（原子、可逆）
→ [Files] 铺新文件
→ register --dir "{app}" 重新登记并启动
→ 成功：删除 {app}.previous
```

### 卸载

```
卸载器询问「是否同时删除配置与日志？」（默认否）
→ usUninstall: NetAnchor.Cli.exe unregister [--purge]
→ 失败：弹窗中止，文件保留在 {app}，可修正后重试
→ 成功：Inno 继续删除文件与卸载项
```

`{app}` 里的文件归 Inno，服务与注册表归 CLI——两边不交叉删除。

## 4. 干净升级与失败保护

| 阶段 | 失败时 |
|---|---|
| 前置检查（只读：服务键、`{app}\NetAnchor.Cli.exe`、降级确认、磁盘） | 直接中止，旧版本未动 |
| `prepare` 非 0 | 中止，旧版本未动 |
| 残留服务登记（目录已删） | 弹窗提供一键清理：选“是”执行 `sc stop` + `sc delete` 后按全新安装继续，选“否”止步并给出手动命令 |
| 旧目录改名失败 | 中止，旧版本未动（提示重启后再试） |
| 复制中途失败 | `DeinitializeSetup` 把 `{app}.previous` 放回并重新登记 |
| `register` 非 0 | 立即回滚：`prepare` 停新服务 → 删半成品目录 → 恢复旧目录 → 用旧目录重新 `register` |

"干净"指两件事：旧目录整体挪走（不留 `pywintypes314.dll` 这类历史残留），以及 `register` 把服务 ImagePath 重指到 `{app}`（不会出现"服务指向旧路径、文件却是新的"）。

升级时目录页锁定：跨目录升级会让 `.previous` 回滚模型失效，换目录请走 CLI 的 `uninstall` + `install`。

## 5. 语言

**简体中文是验收项，不是可选项**：

- 必须存在简体中文，且为默认语言
- 安装、升级、卸载的全部向导页与用户可见提示都是简体中文
- 英文只是附加选项，不能替代中文
- 编译器自带翻译若与当前版本不匹配，用 `[CustomMessages]` 补，**不退回英文**

## 6. 静默与代码签名

静默安装/升级（Inno 标准参数）：

```powershell
NetAnchor-Campus-0.5.1-setup.exe /VERYSILENT /SUPPRESSMSGBOXES /NORESTART
```

**静默模式下的托盘自启项**：Inno 在静默安装时不会自动勾选任何任务。
为避免 `/VERYSILENT` 静默把机器上已有的自启项删掉，安装器的规则是：

| 调用方式 | 自启项 |
|---|---|
| `/VERYSILENT`（不带 `/TASKS`） | **保持开启**（与交互安装的默认一致） |
| `/VERYSILENT /TASKS="!autostart"` | 关闭并清理已有注册项 |
| `/VERYSILENT /TASKS="autostart"` | 开启 |

**`/DIR` 含空格必须整体加引号**：`/DIR=D:\Program Files\...` 会在空格处被截断，装到 `D:\Program`。正确写法：

```powershell
Start-Process 'NetAnchor-Campus-0.5.1-setup.exe' -ArgumentList `
  '/VERYSILENT','/SUPPRESSMSGBOXES','/NORESTART','/DIR="D:\Program Files\NetAnchor-Campus"'
```

安装包自带的 `[Run]` “立即启动托盘”带 `skipifsilent`，所以静默安装后托盘不会立即出现，
下次登录由 `HKLM` 自启项拉起。

当前**未签名**：SmartScreen 会提示"未知发布者"。拿到证书后：

1. 在 `build\installer.iss` 的 `SignTool=` 填 `signtool` 配置名（Inno 的 `Sign Tools` 定义）
2. 在 CI 里用 Secrets 提供 PFX

## 7. 验收清单

| 项 | 期望 |
|---|---|
| 安装向导语言 | 全程简体中文，且默认选中 |
| 全新安装 | 服务 `AUTO_START` + 运行中；`HKLM\...\Run\NetAnchor-Campus Tray` 存在；托盘出现且角标为绿色 |
| 勾掉自启任务安装 | 上述 Run 项不存在（含从旧版本升级时被清掉） |
| 升级 | `prepare` 成功、服务回到 running、配置与凭据未丢、`{app}.previous` 已删除 |
| 升级中被中止 | 旧版本文件与服务完好（可通过在复制阶段取消验证） |
| 卸载（保留配置） | 服务与文件消失，`%ProgramData%\NetAnchor-Campus` 仍在 |
| 卸载（删除配置） | `%ProgramData%\NetAnchor-Campus` 一并消失 |
| 静默安装 | `/VERYSILENT` 无人值守完成，退出码 0 |
| 体积 | 安装包约 **61.5 MiB**（0.4.0 实发版本实测；本机构建 60.3 MiB） |

## 8. 发布流程

仓库已配置两个 GitHub Actions 工作流：

| 工作流 | 触发 | 做什么 |
|---|---|---|
| `ci.yml` | push 到 main / PR | Windows 上 3.12、3.13、3.14 三个版本跑 pytest |
| `release.yml` | 推 `v*` 标签 | 跑测试 → 校验标签与版本一致 → 装 Inno Setup 6 → 构建 → 上传 artifact → 建 **草稿** Release |

发布一个版本：

```powershell
# 1. 版本号两处必须一致：pyproject.toml 与 src/netanchor/__init__.py
# 2. 提交后打标签
git tag v0.5.1
git push origin v0.5.1
```

标签与版本不一致时工作流会直接失败，不会产出张冠李戴的包。

`workflow_dispatch` 手动触发时只构建并上传 artifact（保留 14 天），**不建 Release**，用来验证流水线而不污染发布列表。

发布说明**由工作流从 `CHANGELOG.md` 的当前版本段生成**：正文结构是“本次变更 + 安装方式 + 文件校验”，其中以 `- 文档：` 开头的条目会被过滤掉（它们对用户没有信息量）。

Release 仍然是**草稿**，建议发布前在 GitHub 上过一遍正文：工程口吻的条目改成用户能读的说法，必要时补上升级说明。发版前必须先把 `CHANGELOG.md` 的版本段写好，否则工作流会报错。

Release 默认是**草稿**，发布前需要人工点“Publish”。草稿里只放 `setup.exe` 与 `SHA256SUMS.txt`，
不提供 Portable ZIP（理由见第 1 节）。

## 9. 未验证 / 已知风险

- 杀软误报（R6）：onedir 216 MB + 自解压安装器仍是高风险形态，需要发布后观察
- 未签名：SmartScreen 会提示“未知发布者”，需要用户手动绕过
- 第 7 节清单已在一台已装机器上走完（升级、静默、卸载两分支、失败保护均通过），
  但**未在干净虚拟机上验证**——那里才能暴露“目标机器没有 Python / VC 运行库”这类依赖问题
- 装到 `D:\Program` 这种错误路径：静默参数 `/DIR` 含空格时未加引号会被截断（见第 6 节）
