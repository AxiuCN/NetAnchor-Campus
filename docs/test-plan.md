# 测试计划

> 配套：[architecture.md](architecture.md)。本文件随实现推进更新。
> 原则：能在离线层验证的不放到真机；真机只做"必须在那台机器上才是真的"的事。

## 1. 分层

| 层 | 内容 | 网络 | 环境 | 失败含义 |
|---|---|---|---|---|
| L1 单元 | 配置解析/迁移/原子写、Machine DPAPI 往返、JSONP 解析、退避序列、状态机、IPC 帧编解码 | 无 | 任意 | 代码缺陷 |
| L2 桩集成 | 本地假门户（可控返回码/超时/坏 JSON/验证码恒错）+ 假 IPC 客户端 | 仅回环 | 任意 | 协议实现缺陷 |
| L3 系统 | 服务安装/卸载、注销存活、切换用户、托盘退出、崩溃恢复、重启自启、内存 | 本机 | VM（管理员） | 服务/部署缺陷 |
| L4 真机 | 真实登录、断网重连、门户地址核对 | 校园网 | 宿主机 | 真问题 |

L1/L2 必须可完全离线运行；需要网络时一律标记 `skip`，不伪装成失败。

## 2. 环境与执行者

| 角色 | 位置 | 权限 | 能做什么 |
|---|---|---|---|
| 开发/调试 | VM | 管理员（本地） | 全部 L1–L3，只读联调 |
| 验收 | 宿主机（校园网） | 管理员 | L4 真实登录与断网重连 |

红线：VM 内**不提交真实登录/注销**，只做只读探测与桩测试。

## 3. 优先验证项（按决策顺序）

| # | 验证 | 通过标准 | 层 |
|---|---|---|---|
| 1 | 注销后服务存活 | 注销前记录服务 PID 与日志时间；登录 5 分钟后：PID 未变、日志有持续检测记录 | L3 |
| 2 | 快速切换用户 | 切换往返 3 次：服务 PID 不变、IPC 可连、状态持续更新 | L3 |
| 3 | 托盘退出 | 结束 Tray 进程：服务 PID 不变、服务继续按间隔检测 | L3 |
| 4 | 服务异常恢复 | `taskkill /f` 服务进程：SCM 在 30 s 内拉起新 PID、日志记录恢复、状态自动继续 | L3 |
| 5 | 内存占用 | S1–S4 四态实测表，OCR 子进程策略有数据支撑 | L3 |
| 6 | 认证重试 | 桩门户强制前 2 次校验失败：第 3 次成功；退避序列与配置一致；不刷日志 | L2 |
| 7 | 真实重连 | 断网后自动登录成功、状态回到 ONLINE | L4 |

## 4. 阶段门禁

每个阶段结束后按下表判定，未通过不进入下一阶段。

| 阶段 | 门禁 |
|---|---|
| P1 服务骨架 | 可安装/卸载；`sc query` 状态正确；注销/FUS/托盘退出后服务存活；崩溃后 SCM 自动拉起；S1/S2 内存有数据；pywin32 兼容性有结论 |
| P2 认证核心 | L1 全绿；L2 桩覆盖成功、校验失败重试、门户不可达、超时、坏 JSON；退避序列正确；离线可跑 |
| P3 IPC + 配置 | 交互用户可读状态、可改配置与凭据（不要求提权）；改门户地址时必须同时提交密码，否则 `reauth_required`；手工改文件后旧密文不可用；配置文件普通用户不可读；DPAPI 跨用户会话可解密（服务侧）；日志无凭据 |
| P4 托盘最小版 | 显示状态、改配置、手动重连、打开日志；断连时状态正确刷新；服务未运行时明确提示 |
| P5 打包与安装 | onedir 产物在无 Python 环境运行；install/upgrade/uninstall 三步可重复执行；升级失败可回滚 |
| P6 真机 | 第 7 项通过；日志能定位失败原因；无凭据泄漏 |

## 5. 桩门户故障矩阵（L2）

| 场景 | 桩行为 | 期望 |
|---|---|---|
| 正常 | getCode 200、check_captcha 前 2 次 result=0、第 3 次 1、login result=1 | 3 次内成功，记录每次尝试 |
| 验证码恒错 | check_captcha 恒 0 | 达到 `max_captcha_attempts` 后放弃本轮，进入退避 |
| 取码 500 | getCode 返回 500 | 记录协议错误，退避重试，不崩溃 |
| 取码超时 | 延迟 > `connect_timeout_seconds` | 记网络超时，进入退避 |
| 登录坏 JSON | login 返回非 JSON | 记录解析失败，不崩溃 |
| 门户不可达 | 候选全部连接拒绝 | 状态 `PORTAL_UNREACHABLE`，不请求登录接口 |
| 在线判定异常 | check_url 返回 200 而非 204 | 视为离线，触发重连流程 |

## 6. 内存测量方法

**工具**：`tools/measure_memory.py`（P1 落地），对目标 PID 定时采样并输出 CSV。

**指标**：`WorkingSet64`、`PrivateMemorySize64`、`PeakWorkingSet64`。

**采样**：每秒 1 次，持续 60 s，取后 40 s 的均值与峰值。

| 状态 | 构造方式 |
|---|---|
| S1 服务空闲 | 服务启动、监控停止，静置 60 s |
| S2 持续监控 | 启动监控、保持在线（不触发 OCR），静置 60 s |
| S3 OCR 认证 | 通过测试钩子强制一次取码+识别（不登录），采样 60 s |
| S4 回收后 | OCR 子进程空闲退出后再静置 60 s |

**报告格式**：

| 状态 | 服务 WS | 服务 Private | OCR 子进程 WS | 峰值 |
|---|---|---|---|---|
| S1 | | | — | |
| S2 | | | — | |
| S3 | | | | |
| S4 | | | — | |

**决策口径**：S2−S1 < 30 MB → OCR 进程内懒加载；否则子进程。结论写入架构文档 D7。

## 7. 服务生命周期测试脚本（L3）

| 用例 | 步骤 | 判据 |
|---|---|---|
| 安装 | `NetAnchor.Cli.exe install` | 服务存在、Running、启动类型 auto |
| 注销存活 | 记录 PID → 注销 → 重新登录 → 查 PID 与日志 | PID 不变、日志连续 |
| 切换用户 | 切到另一账户再切回，重复 3 次 | PID 不变、IPC 可用 |
| 托盘退出 | 结束 Tray 进程 | 服务 PID 不变 |
| 崩溃恢复 | `taskkill /f /pid <service>` | 30 s 内新 PID、日志有恢复记录 |
| 重启自启 | 重启虚拟机 | 登录前服务已在 Running |
| 升级 | 二次执行 `upgrade` | 配置保留、服务恢复 Running |
| 卸载 | `uninstall` | 服务与目录移除、ProgramData 按询问保留或删除 |
